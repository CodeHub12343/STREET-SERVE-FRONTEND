C-01/02 — brand first, friction never

  • Splash establishes the identity ("See good, do good") with a warm gradient and the logo lockup — a genuine brand moment, then straight into value, not a wall.
  • The 3-slide carousel maps exactly to the three user surfaces (find / earn / run), and "I already have an account" is always one tap away so returning users never sit through the pitch.

C-03/04 — passwordless by design

  • Phone-first OTP (email as an equal toggle) — no password to create or forget, and phone verification doubles as the baseline anti-fraud signal every account needs (Security §4).
  • OTP failure is the one error state spec'd in the flows doc: the boxes shake red and show "2 tries left," counting down to the 3-failure lockout — never a silent or vague failure. Type 0000.. to see it.
  • Resend is time-gated with a visible countdown, standard anti-abuse for OTP.

C-05/06 — minimal gate, additive roles

  • Profile asks only name + city; photo is explicitly optional — friction scales with money movement, not with browsing (the core onboarding principle from the UX doc), so nothing here blocks a user who just wants to look at the map.
  • Role intent sets a starting mode, and the copy states plainly that all roles live on one account and are addable later — reflecting the additive-roles identity model, so no one feels locked into a single choice.

C-07/08 — earn the permission before asking

  • Both primers are pre-permission screens shown before the OS dialog — they explain the value and, critically, the privacy guarantee ("precise location never shown to others") so the actual OS prompt has context and a far higher accept rate.
  • Each has a real "Not now" path — declining location falls back to the city-level map (C-10's error state), never a dead end.
  • The notification primer previews an actual notification, so the user sees exactly what they're opting into (the fuzzing/precision policy flagged in the requirements is surfaced right here).

C-09 — coach marks, not a screen

  • The tutorial is an overlay on the live C-10 map (spotlight + coach card), not a separate fake screen — the user learns by looking at their real map, and it's fully skippable at every step.
  • Three beats only: tap a pin, wave down, watch the discount — the minimum to make the core loop legible, then out of the way.

Handoff notes

  • C-03/04 call `POST /auth/register` → `POST /auth/verify-otp` (API §1); tokens issued only on OTP success. Managed auth provider (Auth0/Clerk) owns credential/session handling per Architecture §5.
  • C-06 role selection maps to a `user_roles` row; verification tiers are requested later, only when a role first touches money (Flow 1).
  • Location precision choice from C-07 writes to the user's privacy settings, honored by the map's pin-fuzzing logic (Security §2).
