S-01 — reducing first-sale anxiety

  • The "$0 cost if unsold" statement is a standalone highlighted block, not buried in body copy — directly implements the UX doc's "biggest risk is a first-time seller feeling they might lose money" rule.
  • Secondary text entry point ("I'm coming from a shelter partner") sits below the primary CTA, not hidden in a menu — the shelter path is a first-class front door, not an edge case.

S-02 — one wizard, two gates

  • Tier strip (Bronze/Silver/Gold) stays visible throughout so a seller always knows what unlocks next, even mid-verification.
  • Standard path: ID → selfie → bank, gated to Bronze at minimum.
  • Shelter-Cosigned path (toggle above phone): replaces ID/bank steps with an in-person staff-verifier flow — same destination (a working seller account), no KYC artifacts required, per the Q4 recommended default (shelter liability capped to the specific starter allocation).

S-03/S-04 — inventory discovery

  • Hub pins use a distinct rounded-square "box" shape (vs. the circular business pins on C-10) — sellers should never confuse a consignment hub with a live customer-facing vendor pin at a glance.
  • Product detail leads with the seller's own economics (split %, return window, declared value) before anything else — this is a work decision screen, not a marketing page.
  • Seller Agreement checkbox gates the Reserve button — codifies the bailment liability model (Q2 recommended default) at the exact moment it becomes relevant, not buried in a signup flow days earlier.

S-05/S-06 — reservation & QR checkout

  • Quantity stepper shows live "potential earnings" — ties effort directly to payoff, reinforcing the "no capital, real income" pitch from S-01.
  • QR scan uses a real camera-viewfinder metaphor with a scanning animation (collapses to static under reduced motion); the checklist below builds confidence that all three required capture steps (code, condition photo, quantity confirm) happened, per FR-8.2.
  • Success screen restates the return deadline and zero-cost framing one more time — the promise from S-01 is still true at the moment it starts to matter.

Handoff notes

  • ID upload and selfie liveness proxy to the KYC provider (Persona/Stripe Identity) per Architecture §5 — StreetServe never stores the raw document, only a provider reference + status.
  • Checkout writes an `inventory_checkouts` row with condition photo URL, checked_out_at, expected_return_at (Database §3) — QR scan is the trigger, not a manual form.
