C-11/12/13 — three ways into the same map data

  • Search surfaces live results with status + ETA inline, plus recent-search chips — most searches are a business name or a category, so both are one tap.
  • C-12 List view is the accessibility-mandated parity surface (§1 UX rule): everything the map shows, as a sortable, screen-reader-friendly list — never a lesser fallback, a genuine equal with a map/list toggle.
  • Category browser shows the curated ~18 launch categories grouped by top-level tab, with live "N nearby" counts — honest about the pilot's real taxonomy size (Q8), not a fake 100-category grid.

C-15/16 — menu & reviews reuse C-14's pieces

  • The full menu is the expanded version of C-14's preview — Today's Special pinned on top, add-to-order building toward C-21. One consistent menu component, two contexts.
  • Reviews lead with a rating distribution, and the composer is gated to "you ordered here" (transaction-verified) — the anti-manipulation rule (Security §4) made visible with the "Verified" badge on every review.

C-17 — Block Party is a moment, and looks like one

  • A pulsing halo marks the convergence zone, and the sheet frames it as an event ("3 vendors just converged") with each vendor's hook and first-in-line discount — turning the FR-4.2 detection into something a customer wants to run toward.
  • Reuses the exact status rings and discount chips from everywhere else — no new vocabulary for a special moment.

C-25 — one history, every interaction type

  • Orders, wave-downs, bookings, and gifts in a single unified feed with filter chips — matching the Database decision that a customer's history isn't split by transaction type. Active items (track, confirmed booking) float above past ones.
  • Past rows restate savings ("saved $3.15") — the discount payoff stays visible even in history.

C-28/29 — gifting, both sides

  • Sender flow ends in a payment; the gift card preview makes the intangible (a mobile-vendor credit) feel like a real gift. Refund-after-14-days is stated up front (FR-6.1).
  • Recipient redemption offers both a human-readable code and a QR — a vendor on the move might not have a scanner handy, so the code is the reliable fallback. Expiry is always visible.

C-30 — Spot Me leads with trust, not debt

  • The requester sees their own Trust Score and likelihood of acceptance before asking — sets honest expectations (FR-6.3), and the copy is explicit that late repayment is a reputation consequence, never collections, consistent with the platform ethos.
  • Gated by the 30-day / Bronze rule at the system level (PRD §3) — this screen only appears for eligible accounts.
