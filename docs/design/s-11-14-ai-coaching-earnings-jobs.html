S-11 — one recommendation at a time

  • Direct implementation of the UX doc's progressive-disclosure rule: a stacked-card deck shows exactly one actionable recommendation, with the next peeking behind it — never a dashboard of numbers on day one.
  • Every card carries a "Recommended because" line (FR-9.1's explainability requirement) — concrete and falsifiable ("3 sellers averaged $40+ there"), not a vague "AI thinks you'll like this."
  • The "Smart · gets better with data" badge is the Q6-mandated copy — never claims full predictive AI for the rule-based v1.

S-12 — coaching is a library, not a conversation

  • Objection picker (not a free-text chat input) — FR-9.3 specifies scripted responses keyed to logged objection categories, not live conversation transcription. The UI should never look like it's listening to the actual customer interaction.
  • AI suggestion bubble is visually distinct (blue-tinted, badged) from a real conversation transcript — this is coaching content, not a chat log, and should never be confused with one.

S-13 — earnings as a home base

  • Weekly total leads, same big-number treatment as settlement (S-10) and customer savings (C-24) — one consistent "here's the number that matters" pattern across the entire app.
  • Payout history mixes consignment settlements and Jobs gigs in one feed — a seller's income doesn't care which product line it came from, so the ledger doesn't force an artificial split.
  • Sparkline uses a real filled-bar treatment with the peak day emphasized, not a decorative flourish — it's the one piece of data visualization in seller mode and earns the same care as a settlement number.

S-14 — Jobs as the AI's fallback suggestion

  • Jobs exists partly as the answer to S-03's empty state ("nothing to sell nearby? try a gig instead") — the flat-fee framing (vs. consignment's per-unit math) is a deliberately different mental model, shown as a plain, comparable dollar figure per card.
  • Check-in is geofence-confirmed, not a manual "I'm here" button a worker could fake from home — matches FR's check-in/check-out requirement for Jobs.

Handoff notes

  • S-11 recommendations come from `GET /ai/recommendations/products` and `/locations` (API §13); `reason_summary` is a required field on every `ai_recommendations` row (Database §3), not optional copy the client invents.
  • S-12 posts the objection category to `POST /ai/sales-coaching` and renders the returned scripted response verbatim — no on-device generation.
  • S-14 check-in/out calls `POST /jobs/:id/check-in` and `/check-out` (API §11), gated on device geofence, triggering payout on check-out per FR.
