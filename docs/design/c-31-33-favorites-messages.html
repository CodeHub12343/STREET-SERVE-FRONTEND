C-31 — Favorites is a status board, not a list

  • Every row shows the same status ring + chip vocabulary from C-10/C-14 (driving/parked/away) — a customer should be able to scan Favorites the way they'd scan the map, without re-learning what the colors mean.
  • "Just went Driving" gets a subtle ping animation on the pin (simulate below) — the visual echo of the map's live pulse, so Favorites feels like a filtered view of the same live world, not a separate static list.
  • Genuine empty state for a new account — not a placeholder, since most customers will see this before they've followed anything.

C-32 — unread state carries real information

  • Unread threads bold the preview text and show a solid accent dot — deliberately more assertive than a typical muted "new message" treatment, since a reply from a business is often time-sensitive (e.g., "yes, we have your item today").
  • "You: " prefix on the preview when the customer sent the last message — distinguishes "waiting on them" from "they're waiting on you" at a glance, without opening the thread.

C-33 — scoped, not a general DM

  • Context banner ("Asking about: Taco Loco — Main St & 5th Ave") stays pinned above the conversation — reinforces that this is a scoped business inquiry thread, not an open-ended chat, per the narrow-scope rule in the flows doc (menu/hours/location questions, not a social feature).
  • Quick-reply chips (What time until? / Take card? / Specials today?) front-load the most common question types — most of these threads are a single question and answer, so the composer shouldn't assume a customer wants to type from scratch.
  • "Usually replies in minutes" sets expectation without being a hard SLA promise — different from the wave-down 5-minute countdown, since messaging isn't time-boxed the way a live request is.

Handoff notes

  • C-31 reads `GET /users/me/favorites` (API §4a); status rings update live via the same `/live` socket subscription C-10 uses, scoped to just the followed business IDs rather than a bounding box.
  • C-32/33 back onto `message_threads`/`messages` (Database §1) and the `/messages/:threadId` socket namespace (API §3) for live delivery — no polling.
  • Quick-reply chips are static client-side suggestions, not AI-generated — keeps this screen simple and fast, unlike S-12's AI coaching library which is a genuinely different feature.
